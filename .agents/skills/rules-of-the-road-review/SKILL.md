# rules-of-the-road-review

Check a diff (or a plan) against Forestrie's **fundamental invariants**, the
rules of the road: the platform rules in
[forestrie/protocol `rules/platform.md`](https://github.com/forestrie/protocol/blob/main/rules/platform.md)
and each repository's own `docs/rules.md` (devdocs ADR-0071 section 7,
ADR-0074). Use this as the design-invariant pass of a code review, or
standalone when you only want the "does this break something load-bearing?"
check.

This is the fast, high-signal pass. It does **not** replace
[review-changes](../review-changes/SKILL.md) (stack detection, security,
tests, Linear follow-ups); it is its design-invariant core, made reusable.

## 1. Load the rules

1. **The digest is already in context.** A normalised repository commits
   `.claude/rules/rules-of-the-road.md`, generated by `dox digest`: every
   platform and repository rule id with its one-line imperative, and the
   pinned protocol tag. Use it to pick the rules the diff can touch.
2. **Open the full text only for those rules.** Platform: protocol
   `rules/platform.md` at the tag the digest names. Repository: that repo's
   `docs/rules.md`. A rule's **Why**, source link and **Enforced-by** are
   there.
3. **Not yet moved.** A repository whose rules have not moved in yet still
   has them in forestrie-agents `rules-of-the-road/<repo>.md` (local
   `$FORESTRIE_AGENTS`, default `~/Dev/personal/forestrie/forestrie-agents`,
   or GitHub).

| Changed paths | Rules |
|---------------|-------|
| ranger / sealer / custodian / sharder (Go) | arbor `docs/rules.md` (A) |
| SCRAPI / ingress DO / x402 / delegation coordinator (Workers) | canopy `docs/rules.md` (C) |
| Solidity / on-chain | univocity `docs/rules.md` (U) |
| BYOK operator UI / delegation agent / signer | mandate `docs/rules.md` (M) |
| Bun/citty CLIs / contract deploy / deploy-web | univocity-tools `docs/rules.md` (T) |
| Terraform / GKE / DNS / storage | forest-1 `docs/rules.md` (F) |
| GitOps manifests / release qualify/promote | arbor-flux `docs/rules.md` (FX) |
| Anything | protocol `rules/platform.md` (P) |

Load more than one repository's rules only when the change is genuinely
cross-repo. Determine changed paths from `git diff --name-only $BASE...HEAD`
(base per [review-changes §2](../review-changes/SKILL.md)).

## 2. Check the diff against each loaded rule

For every rule in the loaded files, state one of:

- **UPHOLDS** — the change is consistent with the rule (only note if relevant).
- **VIOLATES** — cite the rule id, the offending `file:line`, and the concrete
  failure mode. This is a **High**-severity finding by default: rules of the
  road are load-bearing.
- **AT RISK** — the change moves toward violating it, or relies on an
  assumption the rule forbids (e.g. designing against succinct absence proofs,
  P13).
- **N/A** — rule does not touch this diff.

A rule tagged `⤷ specialises P#` is the concrete check for that platform rule
in this component — a violation there is also a platform violation; cite both
(e.g. `canopy/C1` + `P2`).

## 3. Check the plan and the rules file

- **Plan.** The plan the PR links (forestrie/work) has a `## Rules check`
  section. Every rule the diff touches is listed there, marked honoured or
  amendment proposed with a link. A touched rule missing from it, or an
  amendment with no link, is a finding.
- **Rules file changed.** A diff to `docs/rules.md` or protocol
  `rules/platform.md` must bump `version` (MAJOR removes or redefines a
  rule, MINOR adds one, PATCH rewords) and `amended`, regenerate the digest
  (`dox digest`; CI's `digest-fresh` fails otherwise), tick **rules** in the
  PR's Docs impact block, and link the ADR that motivated it.
- **Enforced-by.** A new rule whose Enforced-by is only `review` is fine,
  but say so: it joins the mechanisation backlog.

## 4. Report

- Findings first, most severe first, each: `rule-id — file:line — what breaks`.
- Then a one-line **verdict**: any VIOLATES → request changes; only AT RISK →
  comment; all clear → note which rules were checked so the pass is auditable.
- Cite rules by id in Linear follow-ups so remediation is traceable to the
  invariant.

Do not restate rule bodies in the report — cite the id; the reviewer can open
the file.
